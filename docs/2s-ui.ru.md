# 2S-UI: панель sing-box с персональными подписками

[🇺🇸 English](2s-ui.md) · [🇷🇺 Русский](2s-ui.ru.md) · [К README](../README.ru.md)

[Установка](#установка) · [Домен подписок](#отдельный-домен-подписок) · [Управление](#управление-и-резервные-копии) · [Диагностика](#диагностика) · [Тесты](#проверки-разработчика)

Режим устанавливает [2S-UI v1.8.3](https://github.com/shenaba/2s-ui/releases/tag/v1.8.3)
со встроенным sing-box 1.14.1, SQLite и Nginx через Docker Compose. Установщик
настраивает VLESS Reality, Hysteria2, HTTPS, случайные данные администратора и
персональные подписки. После установки остаётся создавать клиентов и задавать лимиты.
Это форк S-UI; не путайте его с 3x-ui, которая использует Xray.

## Установка

Нужна чистая Ubuntu 22.04, 24.04 или 26.04 на amd64/arm64, Python 3 и root-доступ.
Требуются Docker Engine 28+ и Compose v2. Если Docker отсутствует, скрипт установит
пакеты Ubuntu; уже установленный старый Docker нужно предварительно обновить.
Автоматического переноса работающей Remnawave или standalone-установки нет.

1. Создайте DNS-only **A**-запись `panel.example.com` на публичный IPv4 VPS.
   Для этого режима не используйте CDN-проксирование и AAAA-записи.
2. Разрешите в firewall провайдера `80/tcp` для Let's Encrypt, `8443/tcp` для HTTPS,
   `443/tcp` для VLESS и `443/udp` для Hysteria2. Сохраните доступ к SSH.
3. Выполните из каталога репозитория на VPS:

```bash
cp .env.2s-ui.example .env
nano .env
sudo bash install.sh
sudo cat /opt/proxy-bootstrap/2s-ui/credentials.txt
```

Задайте `PANEL_DOMAIN`, `LETSENCRYPT_EMAIL`, `REALITY_SERVER_NAME` и
`HYSTERIA_MASQUERADE_URL`. За NAT облачного провайдера явно задайте `SERVER_IPV4`.
Пустой `HYSTERIA_DOMAIN` использует домен панели. Можно отключить один протокол через
`ENABLE_VLESS=false` или `ENABLE_HYSTERIA=false`; хотя бы один должен остаться включён.

Откройте `https://panel.example.com:8443/app/` и войдите с созданными данными.
В разделе **Clients** создайте клиента, выберите подготовленные подключения
**VLESS Reality** и/или **Hysteria2**, установите срок действия и лимит трафика.
Скопируйте ссылку подписки в Hiddify/Happ. Сохраняйте случайно сгенерированное имя
клиента: 2S-UI использует его в `/sub/<client-name>`, поэтому это секрет доступа.
Для понятной подписи используйте поле remark.

Обычная подписка содержит закодированные ссылки протоколов. `?format=json` выдаёт
JSON-конфигурацию sing-box, `?format=clash` — Clash. В JSON-шаблоне настроен IPv4 DNS.
Клиенты, импортирующие обычные ссылки, управляют DNS и маршрутизацией самостоятельно.
Docker-сеть этого режима не имеет выхода по IPv6. Используйте в таких клиентах
IPv4-only, если отдельно не настроили и не проверили IPv6 в Docker.

`HYSTERIA_OBFS_TYPE=salamander` включает обфускацию со сгенерированным общим секретом;
пустое значение её отключает. Другие типы обфускации этим режимом не поддерживаются.
Настройки Xray `minClientVer` здесь нет.

## Отдельный домен подписок

При желании до установки задайте:

```env
PANEL_DOMAIN=panel.example.com
SUBSCRIPTION_DOMAIN=sub.example.com
PANEL_HTTPS_PORT=8443
```

Создайте для `sub.example.com` DNS-only A-запись на ту же VPS. Сертификат покроет оба
домена. Панель останется на `https://panel.example.com:8443/app/`, подписки будут
использовать `https://sub.example.com:8443/sub/<client-name>`. HTTPS-порт общий.
На домене подписок разрешены только GET/HEAD-запросы подписок; панель и API
администрирования возвращают `404`. Домен панели также продолжает выдавать подписки.
Пустой `SUBSCRIPTION_DOMAIN` использует домен панели.

Смена доменов или портов на установленном сервере не автоматизирована. Редактирование
`.env` не переносит существующие подписки и не переписывает настройки панели.

## Управление и резервные копии

| Действие | Команда |
| --- | --- |
| Проверить панель и ядро | `sudo bash scripts/healthcheck.sh` |
| Проверить подписки и трафик | `sudo bash scripts/2s-ui.sh smoke-test` |
| Создать резервную копию | `sudo bash scripts/2s-ui.sh backup` |
| Обновить до закреплённых в репозитории образов | `sudo bash update.sh` |
| Удалить контейнеры, сохранить данные | `sudo bash uninstall.sh` |
| Удалить данные после создания копии | `sudo bash uninstall.sh --purge` |

Состояние, секреты, SQLite, сертификаты и runtime находятся в `/opt/proxy-bootstrap/2s-ui`.
Bootstrap сохраняет ключи до создания объектов и возобновляет незавершённую настройку.
После его завершения повторная установка и обновление сохраняют клиентов, подключения,
TLS и маршрутизацию, изменённые в панели. Переключение режима запрещено; не удаляйте
state-файлы для обхода проверки. Обычное удаление сохраняет установленный режим, пока
его данные явно не удалены через `--purge`.

Перед обновлением создаётся согласованная копия SQLite, затем применяются закреплённые
версии образов. Обновляйте через `update.sh`: встроенное обновление панели меняет слой
контейнера и теряется при его пересоздании Docker. Новые версии образов сначала нужно
закрепить и проверить в репозитории.

Резервные копии включают БД, состояние, runtime, конфигурацию и сертификаты.
Они содержат секреты и хранятся в `/var/backups/proxy-bootstrap/2s-ui/`. Копируйте
их за пределы VPS. Для восстановления на том же сервере с теми же адресами:

```bash
sudo bash scripts/2s-ui.sh restore /var/backups/proxy-bootstrap/2s-ui/ИМЯ_КОПИИ
```

Восстановление проверяет контрольные суммы и целостность SQLite, сохраняет текущую
установку, затем заменяет её и запускает закреплённые контейнеры. Текущая БД заменяется,
включая пользователей, созданных после копии. Для восстановления на пустом сервере
нужно предварительно подготовить Docker, зависимости, DNS и firewall.

Certbot продлевает общий сертификат через `certbot.timer`. Deploy-hook копирует новые
файлы, перезагружает Nginx и перезапускает встроенный sing-box. Скрипты копируются
в runtime, поэтому исходный checkout для продления не нужен. Резервные копии и
сертификаты Let's Encrypt сохраняются даже после `--purge`.

## Диагностика

```bash
sudo bash scripts/2s-ui.sh healthcheck
sudo bash scripts/2s-ui.sh smoke-test
sudo bash scripts/2s-ui.sh smoke-test --external
sudo docker compose --project-directory /opt/proxy-bootstrap/2s-ui \
  -f /opt/proxy-bootstrap/2s-ui/compose.json logs --tail 100 panel nginx
```

Smoke-test создаёт временного клиента на 15 минут с лимитом 100 МБ, получает его
настоящую HTTPS-подписку и проверяет HTTPS-трафик через каждый протокол закреплённым
клиентом sing-box. Также проверяется запрет доступа VPN-пользователей к внутреннему
API панели. Временный клиент и контейнеры удаляются; после прерванного теста очистка
происходит при следующем запуске. Ошибки сохраняются в закрытый `last-probe.log`.

Обычная проверка подключается внутри Docker-сети. `--external` использует публичные
адреса, но всё ещё запускается с VPS: это не подтверждает доступность из сети клиента.
Сравните Wi-Fi и мобильную сеть, выбирая протоколы отдельно. Если подписка и SSH
зависают до того, как пакеты дошли до VPS, проверяйте доступность адреса и фильтрацию
у провайдеров. Смена панели или ядра сама по себе не исправит недоступный IP.

Docker публикует VPN- и HTTPS-порты независимо от обычных правил UFW. API обслуживания
привязан только к loopback; внутренний порт подписок `2096` наружу не опубликован.
Ограничения по источникам задавайте в firewall провайдера. Правила установщика открывают
только TCP/80 хоста для ACME, не сбрасывая политику и правила SSH. Адрес управляемого
Nginx добавляется в доверенные прокси для передачи IP клиента.

`CERTBOT_STAGING=true` предназначен только для тестов. Он ослабляет проверку доверия
к HTTPS и TLS тестового VPN-клиента; обычные клиенты staging-сертификатам не доверяют.
Для рабочей установки используйте `false`.

## Проверки разработчика

```bash
python3 -m unittest discover -s tests -v
python3 tests/integration_2s_ui.py
python3 tests/integration_2s_ui.py --separate-subscription-domain
```

Интеграционные тесты требуют Docker, Compose, curl, openssl и доступ в интернет.
Они публикуют порты только на loopback и проверяют bootstrap, HTTPS-вход, подписки,
трафик, обновление, восстановление и смену сертификата без изменения firewall хоста
и запуска apt/certbot. Полная установка Ubuntu, выпуск/продление публичных сертификатов
и реальные устройства Hiddify/Happ требуют отдельной проверки на VPS.
